# 既知の制限事項

## デバイスの画面がオフになった後に接続が切断される

プログラムが正常に接続された後、コンピューターまたは Android デバイスのいずれかが画面をオフにすると、接続が失われます。プログラムを引き続き使用するには、再起動して再接続する必要があります。

**解決策**: プログラムは現在、「画面をオンのままにする」設定を提供しており、これにより Android デバイスが画面をオフにするのを防ぎ、この制限を軽減できます。

## キーボードとマウスを共有した後、Android デバイスのマウスカーソルが不安定になります。これを修正するにはどうすればよいですか？

マウスのドライバーソフトウェア（例：Logitech G Hub、Razer Synapse など）を使用して、マウスの「レポートレート」（場合によっては「ポーリングレート」とも呼ばれます）を 125Hz または類似の値に調整してみてください。これにより、状況が大幅に改善されるはずです。

## ADB を使用する他のソフトウェアとの競合

Android デバイスに接続するために ADB に依存するソフトウェア（Android Studio など）を使用しながらこのソフトウェアを使用すると、このソフトウェアが Android デバイスに正常に接続できない状況に遭遇する可能性があります。同様に、このソフトウェアを使用して接続した Android デバイスは、ADB を使用する他のソフトウェアによって接続できません。
これは ADB 自体の制限であり、現在解決策はありません。

## Bonjour との競合

[barrier](https://github.com/debauchee/barrier)や[deskflow](https://github.com/deskflow/deskflow)などの一部の類似ソフトウェアは、ネットワーク接続を簡素化するために[Bonjour](https://developer.apple.com/bonjour/)を使用しています。ただし、一部のユーザーからのフィードバックによると、barrier を実行し、コンピューターで Bonjour を開始してからこのソフトウェアを使用すると、このソフトウェアの接続成功率が大幅に低下します。

**解決策**: このソフトウェアと Bonjour の間の競合の正確な原因はまだ不明です。この問題を回避するには、まずこのソフトウェアで接続を試みてから、barrier を開始してみてください。
